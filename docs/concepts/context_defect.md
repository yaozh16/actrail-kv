# 上下文结构缺陷

## 对比对象

分析器不会把所有请求互相比较，而是先按以下 key 分组：

```text
comparison_group_key =
  time_window
  + endpoint_key
  + model_or_deployment_key
  + context_schema_key
  + agent_key（可选）
```

- `time_window`：同一个分析时间窗口，例如同一小时或以当前请求为中心的最近 X 分钟。
- `endpoint_key`：同一个 LLM endpoint 或逻辑路由；不同 endpoint 不共享同一比较组。
- `model_or_deployment_key`：同一个模型或模型部署，避免比较不会共享 KV 空间的请求。
- `context_schema_key`：同一种模型可见请求组织方式，例如相同 payload 结构和 adapter revision。
- `agent_key`：可选维度。启用该维度时，缺失值归入独立的 `unknown` 组，不与已知 Agent 混合；未启用时从 group key 中移除。

只有 group key 相同的请求才会继续抽取模板并相互比较。tool 集合只与 tool 集合对齐，message 序列只与 message 序列对齐，同一逻辑 tool 只与对应 tool 比较。

request ID、trace ID、session ID、tenant、用户输入和其他高频变化值不能默认进入 group key，否则会把本应共同分析的请求提前拆散。若上游存在真实的 KV 隔离 namespace，应将该 namespace 作为额外的必选 key。

## 缺陷判定

上下文结构缺陷统一表示为：

```text
请求 A：P1 / X1 / P2
请求 B：P1 / X2 / P2
```

`P1` 是当前公共前缀，`X1/X2` 是失配区域，`P2` 是失配后重新出现的稳定内容。缺陷的本质是 `X` 过早阻断了 `P2`；system、tool、history、content block 只说明问题出现在哪里。

| `X1/X2` 的关系 | 通用例子 | 判定依据 | 优化启示 | 是否属于结构缺陷 |
|---|---|---|---|---|
| 同一位置的值持续变化 | `P1 / 租户=北区 / P2`<br>`P1 / 租户=南区 / P2` | 同一模板槽位出现多个易变值，之后存在受支持的稳定 `P2` | 在语义允许时，将稳定内容前移或将易变内容后移 | 是 |
| 同一位置存在少数固定变体 | `P1 / 修改前 / 先 / 阅读代码 / P2`<br>`P1 / 修改前 / 务必 / 阅读代码 / P2` | `修改前`、`阅读代码` 形成稳定模板内容；只有中间槽位形成少数固定变体 | 统一配置来源、模板版本或生成方式 | 是；与上一行同属“同一位置内容不同” |
| 同一位置的文本不同，但结构化数据等价 | `P1 / {"a":1,"b":2} / P2`<br>`P1 / { "b": 2, "a": 1 } / P2` | 原始模型可见文本不同；按对应数据类型解析后严格相等 | 使用确定的序列化或格式化方式 | 是；这是对 `X` 的进一步归因，不是独立缺陷类型 |
| 一边中间多出内容 | `P1 / A / P2`<br>`P1 / P2` | `A` 之后能够重新对齐到受支持的稳定 `P2` | 在语义允许时，评估是否可以改为尾部追加 | 是 |
| 两边包含相同内容，但顺序不同 | `P1 / A / B / P2`<br>`P1 / B / A / P2` | `A/B` 能通过稳定且唯一的身份一一对应；重复或歧义身份不算 | 使用稳定、确定的生成顺序 | 是 |
| 差异只位于结尾 | `P1 / X1`<br>`P1 / X2` | 差异后没有可恢复的稳定 `P2` | 无；这是正常动态后缀 | 否 |
| 请求整体结构不同 | 两个请求无法通过局部 `X` 重新对齐 | 不存在可靠的共同模板和恢复位置 | 分为不同模板分析 | 否 |
| 差异不进入模型上下文 | 只有 temperature、trace metadata 或 HTTP 外层 JSON 格式不同 | 模型可见内容没有变化 | 无 | 否 |
| 内容看似相似，但无法可靠对应 | 重复工具身份、歧义 block 或只有文本相似度 | 无法证明同一位置、同一元素或稳定 `P2` | 不给出结构归因 | 否 |

模板和槽位的详细说明见[请求模板](template.md)，具体分析步骤见 [Analyze 流水线](../architectures/analyze/pipeline.md)，报告字段见 [Analyze 输出](../architectures/analyze/output.md)。
