# 结构复用率与优化空间

## 为什么关心复用率

模型服务的前缀缓存只能命中**与之前某次请求完全一致的前缀**。一个多轮 agent 会话里，
如果易变内容（租户名、进度标记、随机 tool call id）出现得太早，它之后的全部稳定内容都无法命中缓存，
每一次都要重新预填充。`actrail-kv` 的目标就是从可观察的请求结构里找出这类损失，并说清"还差多少、能补多少"。

结构复用率就是把这件事压缩成一个数字。

## 统计口径

```text
结构复用率 = Σ 相邻请求对的公共前缀字节 / Σ 相邻请求对的上下文总字节
```

范围限定在同一条会话内**相邻的两个请求**：

- 会话内第 1 个请求没有可比较的前序，**完全不参与统计**（既不进分子也不进分母）；
- 跨会话不比较：不同会话之间不存在"上一轮"；
- 只统计带 `session_key` 的记录；没有会话标识的请求不进入该指标；
- 全程是 UTF-8 **字节**口径，不是 token。

没有会话对时该指标整体缺省（`analysis.json` 中不输出 `prefix_reuse`），报告也不渲染对应区块。

## 三类字节构成

上下文总字节被拆成互不重叠的三段，三者之和**严格等于**上下文总字节：

| 构成 | 含义 | 来源 |
|---|---|---|
| 已复用 | 当前真实能作为前缀复用的字节 | 会话内相邻对的实测公共前缀 |
| 已知可恢复 | 消除已知结构问题后可追加复用的字节 | 缺陷证据中被阻断的稳定字节 |
| 每轮新增 | 该轮新增的内容（工具结果、新一轮对话等） | 总额减去上面两项 |

"每轮新增"按剩余量计算，因此只作量级参考；它说明的是：**这部分内容按前缀缓存的定义不可复用**，
想继续提高复用率需要减少每轮新增量，而不是继续调整内容顺序。

## 可恢复上界

```text
逐请求上限 = 当前公共前缀 + 该请求所涉缺陷中最大的 blocked_stable_bytes
             （封顶为该请求的上下文总字节）
```

同一请求被多个缺陷限制时取**最大值而不是相加**：同一根因常在不同比较组里被重复识别，
相加会重复计数。所有请求的上限之和除以上下文总字节，就是**结构复用率的理论上界**。

这个上界是**估算**，口径要看清：

- 它把"缺陷对齐口径下的被阻断字节"叠加到"会话对口径下的当前前缀"上，两个口径的参照点不同；
- 因此它是**结构上界**，不是可达承诺；
- 它只回答"如果把这些结构问题都消除，前缀最多能延伸到哪里"，不回答需要多少改动成本。

## 与真实 KV 命中率的关系

真实命中率来自上游响应 usage：

```text
真实命中率 = cached_tokens / prompt_tokens        （basis = reported）
```

上游没有返回 usage 时，只能按与上一条请求的 payload 公共前缀估算，
此时 token 字段全部缺省，`hit_rate` 是**字节比**代理值（`basis = estimated`）。

| | 结构复用率 | 真实命中率 |
|---|---|---|
| 口径 | 字节（可观察 payload 结构） | token（上游 usage） |
| 可得性 | 只要带会话标识就能算 | 需要上游返回 usage |
| 用途 | 发现优化空间、给出上界 | 验证结构代理是否可信 |

两者**口径不同，不表示数值应当相等**，只能用来判断方向是否一致。
`actrail-kv` 绝不把结构量换算成 token 或金额，也不会在没有 usage 时声称发生了 KV miss；
报告中的对照表只使用 `basis = reported` 的会话，估算口径的会话单独计数。

## 在报告里的位置

- **首屏刻度条**：当前复用率 → 补完已知结构问题后的上界 → 目标（90%，报告层产品参数）；
- **Top K 表格**：按既有缺陷排序列出"改哪里、被阻断多少、怎么改"，每条可跳到证据；
- **结构代理 vs 真实命中**：逐会话并列两个口径，用于判断结构代理是否可信；
- 当补完已知问题仍达不到目标时，报告会直接说明剩余部分属于每轮新增内容。
