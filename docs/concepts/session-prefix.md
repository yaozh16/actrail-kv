# Session 前缀延续

当采集方为请求提供同一个 `session_id` 时，analyzer 会按采集时间连接相邻请求，观察上一请求已经形成的结构前缀在下一请求中保留到哪里。

```text
R1: H
R2: H + dynamic result X1                    正常追加
R3: H + dynamic result X1 + new user message  正常追加
R4: H + rewritten X1 + ...                    既有历史变化
```

`X1` 第一次出现在 R2 尾部时是新内容，不是历史破坏。R3 原样保留 `X1`，因此它属于 R2 到 R3 的保留前缀。只有 R4 改写、删除或重排已经出现在 R3 中的内容时，才会形成历史变化事实。

## 时间线如何形成

- `session_id` 只能由采集方通过 `X-Actrail-Session-Id` 显式提供；系统不根据内容或时间猜测 Session。
- 同一 Session 按 `captured_at` 排序；时间相同时使用输入行号维持确定顺序，并标记顺序歧义。
- 只比较相邻请求，不进行 Session 内全量两两比较。
- Session 时间线不受模板比较的一小时时间窗口截断。
- 一个 Session 在当前版本中代表线性请求流，不恢复并发分支或父子请求图。

## Transition 分类

| 分类 | 含义 | 是否形成 history site |
|---|---|---:|
| 完全相同 | 两次可观察请求结构一致 | 否 |
| 正常追加 | 当前请求完整保留上一请求的开放前缀，并在尾部增加内容 | 否 |
| 前缀截断 | 当前请求是上一请求开放前缀的真前缀 | 是 |
| 历史变化 | 上一请求结束前发生改写、插入、删除或重排 | 是 |
| 不可比边界 | model、endpoint 或其他已知比较边界改变 | 否 |
| 顺序歧义 | 相邻记录时间相同，无法确认真实先后 | 否 |
| 不可分析边界 | 相邻记录至少一侧无法投影 | 否 |

结束标记不属于开放前缀比较，因此正常追加 message 或 tool 不会因 `messages:end`、`tools:end` 的位置变化被误判为历史变化。

## 指标边界

可比较 transition 给出上一请求字节数、当前请求字节数、保留前缀字节数、前缀保留比例和失效旧后缀字节数。这些值都是可观察请求结构的 UTF-8 字节代理，不代表真实 Token 或 KV 命中量。

history site 只聚合类别、已知比较边界和逻辑位置都相同的 transition；历史变化与前缀截断不会混为一个 site，model、endpoint、adapter 等边界不同的请求也不会混合计量。单次变化可以作为事实展示；同一位置重复发生后才产生优化建议。系统只描述可观察行为，不推断它是摘要、RAG、状态刷新或其他业务原因。
