# C ABI 与兼容契约

状态：0.2.1 已实现契约。ABI 主版本为 1，与业务版本分别管理。公开声明见 `crates/sdk/native/contracts/include/actrail.h`，跨语言布局通过 C 实现与 Rust 宿主集成验证。

## 基础类型与入口

动态库通过 `extern "C"` 导出固定名称的符号。ABI 基础类型在 `crates/sdk/native/contracts/` 定义，采用 C 布局。所有调用限定于同一操作系统、架构及兼容的系统运行库环境。

| 类型 | 表示与用途 |
| --- | --- |
| 输入缓冲区 | 只读字节指针与 `size_t` 长度，内容为 UTF-8 JSON，不要求 NUL 结尾 |
| 输出缓冲区 | 动态库分配的字节指针与 `size_t` 长度，内容为 UTF-8 JSON |
| 实例句柄 | 不透明指针，仅由创建它的动态库操作和销毁 |
| 状态码 | 固定宽度 `int32_t`，0 表示成功，其余表示稳定错误类别 |
| ABI 版本 | 两个固定宽度 `uint32_t`，分别表示主版本和次版本 |

每个库使用独立的符号前缀，例如 `actrail_kv_receiver_`、`actrail_kv_analyzer_`、`actrail_kv_reporter_`。原 `actrail_` 前缀已替换，已有调用方需同步更新符号名称或 Rust SDK。

| 入口后缀 | 输入 | 输出与语义 |
| --- | --- | --- |
| `abi_major` | 无 | 返回 ABI 主版本 |
| `abi_minor` | 无 | 返回 ABI 次版本 |
| `create` | 配置 JSON 缓冲区、句柄输出地址、响应缓冲区输出地址 | 创建实例，返回状态码及响应 |
| `submit` / `analyze` | 对应实例句柄、请求 JSON 缓冲区、响应缓冲区输出地址 | 执行采集写入或按需分析并返回状态码及响应 |
| `render` | reporter 实例句柄、完整分析成功响应 JSON、渲染参数 JSON、响应缓冲区输出地址 | 借用分析数据并返回内存报告 |
| `export` | 本库成功响应 JSON、导出目标 JSON、响应缓冲区输出地址 | analyzer 与 reporter 提供此入口，显式原子写入产物文件，无需业务实例 |
| `destroy` | 实例句柄、响应缓冲区输出地址 | 等待实例资源停止，消费句柄并返回状态码及响应 |
| `buffer_free` | 完整输出缓冲区 | 释放该库分配的缓冲区，不依赖业务实例存活 |

`create` 失败时句柄输出为空。每个返回响应的函数先将输出初始化为空，再写入结果。空输出表示没有响应内存需要回收。有效句柄传给 `destroy` 后始终视为已消费，包括关闭返回错误的情况。

ABI 状态码区分参数或 JSON 错误、配置错误、业务输入错误、存储或 I/O 错误、分析或渲染失败、内部失败。具体数值在首版头文件中固定，发布后不复用。SDK 保留未知非零状态码及原始错误内容。

首版状态码固定为 0 成功、1 参数或 JSON 错误、2 配置错误、3 采集业务输入错误、4 存储或 I/O 错误、5 分析或渲染失败、6 内部失败。声明见[公开头文件](../../../crates/sdk/native/contracts/include/actrail.h)。

## JSON 数据契约

各业务输入和结果的 JSON schema 与 ABI 函数布局分别维护。兼容版本保留字段名称、类型、含义、必填条件和成功语义。新增可选字段可以兼容扩展，新增必填字段或改变原字段类型属于不兼容修改。

响应统一包含 `ok` 和 `schema_version`。成功时携带 `data`，失败时携带 `error`。错误对象至少包含稳定的 `code` 和供人阅读的 `message`，字段错误还包含 `field`。状态码与 `ok` 必须一致，调用者依据 code 而不是匹配 message 分支处理。

Receiver 提交输入示例：

```json
{
  "schema_version": 1,
  "payload": {"model": "example", "messages": []},
  "source": "embedded-agent",
  "session_key": "session-1",
  "comparison": {"endpoint_key": "llm-primary"}
}
```

成功响应示例：

```json
{
  "schema_version": 1,
  "ok": true,
  "data": {"captured_at": "2026-11-26T00:00:00Z"}
}
```

输入缺少 schema 版本或使用不支持的版本时返回明确错误。Receiver 的业务字段规则见[采集服务契约](../receiver/index.md)。SDK 将业务对象序列化后提交，由动态库完成最终业务校验。

Analyzer 的请求指定采集存储来源及筛选参数，按需读取并返回分析产物。已有文件输入能力可作为显式选定的数据来源。其成功响应的 `data` 是现有 schema 的完整分析对象，Rust SDK 将完整响应封装为 `AnalysisOutput`。

Reporter 的 `render` 分别接收完整分析成功响应和渲染参数 JSON。分析缓冲区原样借用 analyzer 的输出，渲染参数单独携带 schema 版本及格式、语言等选项。reporter 校验分析响应的版本与成功状态，再读取 `data`，不调用文件加载入口。`ok` 为 false 的分析响应被拒绝作为渲染输入。

Reporter 返回包含格式及内容的结果，Rust SDK 封装为 `ReportOutput`。HTML 与 Markdown 作为成功响应 `data` 内的 JSON 字符串返回。`analyze` 与 `render` 均仅返回内存产物，大结果的流式接口留待实际需求扩展。

报告响应的 `data.reports` 为数组，每项包含 `format` 和 `content`。未指定格式且实例配置也未指定时返回 HTML 和 Markdown 两项。多格式导出参数需提供 `format`，单格式结果可省略。

分析和报告响应的可选 `source` 字段记录文件输入或已解析存储配置。reporter 原样继承分析来源，显式导出复用输入与存储路径保护。该元数据属于 SDK 响应信封，导出的分析文件只保留现有分析产物 schema。

analyzer 与 reporter 各自导出 `export`，由输出对象的 `export(path)` 调用。导出参数包含 schema 版本和绝对目标路径，SDK 将相对路径按输出对象保留的 `base_dir` 解析。分析导出仅写响应的 `data` 分析对象，报告导出写解码后的 HTML 或 Markdown 正文，两者均不写入 SDK 响应信封。导出失败保留内存输出，文件发布沿用临时文件和原子替换规则。

配置以 JSON 对象中的 `config_toml` 字段整体传入。库内复用已有 TOML 配置契约，避免重新维护一套 JSON 配置默认值。该文本采用完整设置文档的表结构，receiver 读取 `[storage]`，analyzer 读取 `[analyzer]` 和需要的 `[storage]`，reporter 读取 `[report]`。其余模块的表不触发对应模块初始化。HTTP 监听设置仍归 CLI 与 HTTP 通道。`config_toml` 缺省或为 `null` 时读取 `~/.actrail/actrail-kv/settings.toml`，沿用 CLI 的缺项补全与写回机制。传入字符串时使用内存配置，空字符串使用默认值。

创建信封同时要求提供绝对路径 `base_dir`，内存配置中的相对路径以它为基准，文件配置中的相对路径以设置文件所在目录为基准。显式导出参数中的相对路径始终按 `base_dir` 解析。基准在创建时固定，后续宿主改变工作目录不影响路径。动态库路径由 Rust SDK 在调用创建入口前解析为绝对路径。SDK 的直接采集使用 `[storage]` 配置，原 CLI 单文件输出模式继续由其现有入口提供。

创建信封的可选 `overrides` 对象按配置表结构提供显式字段覆盖。优先级为覆盖字段、基础配置、默认值。表递归合并，数组与标量整体替换。Rust SDK 的 `SdkOverrides` 引用从配置定义生成的覆盖类型，未设置字段不序列化。覆盖仅作用于当前实例，不写回设置文件。

SDK 的 `analyze` 不使用 `[analyzer].output` 自动写文件，`render` 不使用 `[report].input` 加载文件，也不使用 `[report].output` 自动导出。这些文件设置继续服务既有 CLI 行为。SDK 文件加载与产物导出由独立显式操作触发，导出目标由方法参数指定。

Rust SDK 提供类型化请求、结果和实例接口，同时允许整体传入原始配置文本。可扩展 JSON 对象保留未知字段，尤其完整分析产物必须能在 analyzer 与 reporter 之间无损转交。类型化解码不删除宿主当前版本尚不认识的分析字段。

SDK 的分析结果封装保留原始 JSON，同时提供已知字段的类型化访问，不直接使用含 `deny_unknown_fields` 的完整业务类型解码新结果。此能力仅保障无损转交。现有 reporter 对分析产物及其 schema 采用严格校验，因此 0.2.0 的兼容算法升级须继续输出既有分析产物 schema。涉及产物字段增加或 schema 变化的发布须明确升级 reporter，不能仅凭 C ABI 一致宣称可独立替换。

分析请求的 `selection` 只覆盖显式字段。`last_n` 缺省时继承实例配置，JSON `null` 清除限制，正整数设置新的上限。Rust SDK 使用 `RecordLimit` 表达这三种情况。

## 内存与调用责任

- 输入缓冲区只借用到当前函数返回。动态库在返回前完成读取或复制，不保留宿主指针。
- 非空缓冲区必须指向有效且在调用期间可读的内存。输出参数必须可写。空指针只允许用于长度为零的输入或约定的空输出，空 JSON 输入仍返回解析错误。
- 输出缓冲区由分配它的库释放。调用者不得修改长度、用宿主分配器释放或重复释放。
- `buffer_free` 接受约定的空输出并直接返回。释放完成后 SDK 清空本地所有权记录。
- 同一库生成的句柄不能用于其他库或其他已加载版本。调用者不得伪造句柄或在销毁后使用。
- Rust SDK 在封装内处理这些约束，对外不暴露裸指针。库句柄的所有权覆盖所有实例、函数指针及待释放缓冲区。

`AnalysisOutput` 持有 analyzer 分配的完整响应缓冲区、原库引用和路径基准。调用 reporter 时只借出只读指针和长度，reporter 不修改或释放分析缓冲区，也不在返回后保留指针。SDK 不为此交接重新序列化完整分析对象，reporter 内部仍执行 JSON 解析和业务校验。

`ReportOutput` 以同样方式持有 reporter 缓冲区。输出对象可独立于业务实例存活，关闭 analyzer 或 reporter 实例不会释放仍被持有的输出。每个输出最终调用原分配库的 `buffer_free` 一次，然后释放库引用。导出入口仅依赖输出及其所属库，不依赖已经关闭的实例。

## 线程、关闭与失败

业务入口为阻塞调用。同一实例的操作串行执行，`destroy` 与业务操作不得并发。Rust SDK 使用独占实例访问实现该约束，不向调用方承诺同一实例的共享并发访问。

需要异步存储的实例持有独立运行时，实例生命周期覆盖保留期清理等后台任务。实现使用库内受控执行线程处理异步工作，调用方线程等待结果，避免在宿主异步上下文嵌套启动 runtime。关闭时完成在途操作、停止后台任务并释放资源。

Rust SDK 提供消费实例的显式关闭方法以返回关闭错误，同时提供析构回收。析构期间不抛出 panic。动态库生命周期至少覆盖最后一次缓冲区释放，本版本升级采用停止宿主、替换库、重启的方式。

FFI 导出层捕获可展开的 Rust panic，将实例标为不可继续执行业务并返回内部错误。panic 不跨 ABI 边界传播。进程 abort、内存耗尽和非法外部指针不属于可恢复业务错误。输入指针和句柄有效性由 C 调用契约以及 Rust 安全封装保证。

## 兼容与发布验证

SDK 先加载固定版本查询符号，要求主版本匹配且次版本满足所需最低值，再解析自身使用的业务符号。主版本不匹配、版本过低或符号缺失时，释放尚未使用的库并返回加载错误。

兼容更新可以增加入口和可选字段，保留旧入口与字段语义。不兼容更新提高 ABI 主版本或对应 JSON schema 主版本，并显式拒绝不匹配的调用。旧 SDK 无需使用新能力即可继续调用兼容的新库。

发布验收使用同一份已编译宿主加载基线库和候选库，比较宿主哈希，验证加载、提交、分析、渲染与关闭。通过受控实现版本差异证明实际执行了新库。增加不兼容版本、缺失符号与旧分析产物读取的案例。

兼容矩阵包含新 analyzer 加旧 reporter，以及旧 analyzer 加新 reporter。改变分析产物 schema 的组合应明确拒绝并给出格式版本错误。

动态导出和加载需要少量 `unsafe`。只对 SDK 的 FFI 和加载模块设置专用 lint 策略与安全注释，核心业务库继续保持 `unsafe_code = "forbid"`。
