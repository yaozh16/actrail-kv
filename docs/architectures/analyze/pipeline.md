# Analyze 流水线

## 输入投影

`CapturedRequest` 保存 `captured_at`、可选 `source` 与未经改写的 `payload`。adapter 将请求中模型实际可见的内容按原始顺序投影成 `CacheSequence`。

投影结果保留：

- system、tool、message 和 content block 的层级；
- role、工具稳定身份和内容单元类型；
- 原 payload 的 JSONPath；
- 文本在原字符串中的 UTF-8 byte range；
- 模型可见内容的原始顺序。

HTTP 外层 JSON 的 object 键顺序和空白不进入投影。模型可见字符串保持原始 UTF-8 内容。

## 选择比较对象

离线 MVP 将一次输入数据集视为分析时间范围。若未来使用滚动分析，同一概念可以对应“某条请求与它之前或前后 X 分钟内的请求”。

对于一条请求，只从该时间范围内选择模型可见组织方式兼容的请求作为候选。model 或 adapter 产生的上下文结构不同，则不直接比较。

整体请求建立候选关系后，只在相同层级之间对齐：

- 完整请求与完整请求比较；
- tool 集合与 tool 集合比较；
- message 序列与 message 序列比较；
- content block 序列与 content block 序列比较；
- 能以稳定身份确认是同一个 tool 时，tool definition 与对应 tool definition 比较；
- 同一文本单元内部的内容与对应文本单元比较。

tool 集合不会与 message 序列比较，一个 tool definition 也不会因为文本相似就与 system prompt 对齐。

## 模板与候选召回

1. 将请求投影为能够回溯到原 payload 的 `CacheSequence`。
2. 按模型可见结构筛出可能属于同一模板的请求。
3. 使用稳定内容签名和有界文本相似度召回候选；长文本使用确定性的 bottom-k shingle，使中部插入或删除不会令后续采样整体错位。
4. 对整体结构兼容的请求进行有界对齐，形成模板稳定内容、槽位和未匹配区域；文本 LCS 保持既有 canonical tie-break，避免重复字符改变模板边界与稳定身份。
5. 为每个模板成员生成同一套模板坐标下的符号序列。

模板抽取不得依赖 tenant、UUID、时间戳等业务字段名或值格式。具体业务内容只作为模板成员和诊断证据。

## 定位前缀失配

在同一模板的成员之间寻找：

```text
请求 A：P1 / X1 / P2
请求 B：P1 / X2 / P2
```

1. 从请求开头确认连续相同的 `P1`。
2. 定位第一个无法继续对齐的区域 `X`。
3. 越过 `X` 后继续对齐，寻找重新出现的稳定内容 `P2`，并扩展到下一个真实差异前的最大连续稳定区。
4. 没有 `P2` 的差异作为正常动态后缀处理，不生成结构问题。
5. `P2` 的成员支持数和连续长度必须达到配置门槛。

“找到 P2”表示能够明确指出差异之后从哪里重新相同，而不是仅凭整个请求的文本相似度推测。

## 分析失配区域

`X1` 与 `X2` 首先按符号结构分为：

- 同一逻辑位置的内容不同；
- 一边多出或缺少内容单元；
- 相同内容单元发生移动或重排。

同一位置内容不同时，继续分析：

- 变体是持续变化，还是集中在少数固定版本；
- 文本内部是否还能拆出稳定前缀、槽位和稳定后缀；
- 内容是否属于可解析的结构化数据；
- 使用与内容类型匹配的规范化后，两个变体是否严格等价；相同非空标签后的完整 JSON 也可参与严格 AST 等价判断。

序列数量或顺序不同时，继续分析：

- 两边的内容单元能否建立稳定的一一对应关系；
- 差异是插入、缺失、移动还是重排；
- 重复身份或对应歧义是否使该结论不可靠。

system、tool、history 和 content block 只作为失配区域的 source scope，不参与决定上述结构类别。

## 跨模板成员聚合证据

同一逻辑失配区域的所有模板成员直接形成变体分组。每个成员在该区域只计数一次，不能把请求两两组合的次数当作支持度。

聚合需要得到：

- 可比较请求总数；
- 每个 `X` 变体的成员数；
- 分歧后支持 `P2` 的成员数；
- 当前公共前缀长度；
- 可恢复的连续稳定内容长度；
- 能够解释该失配的结构事实。

同一个 `P1 / X / P2` 区域只形成一个问题。内容类型、scope 和规范化证据可以同时附着在该问题上，不产生重复问题。

同一模板会沿一条保守 supporter chain 继续扫描，最多输出四个有序、互不重叠的 episode。第一个 episode 保持直接缺陷和 Top K 语义；第二到第四个输出为条件性局部位点，表示更早差异稳定或修复后才可能成为首断点的机会。多个 episode 的字节和影响不得相加。

## Session 相邻请求分析

带 `session_id` 的记录另行组成完整时间线，按解析后的采集时间和输入行号稳定排序，并只比较相邻请求：

```text
Session records
  → append-aware 开放投影视图
  → previous/current 最长公共结构前缀
  → transition 分类与唯一 prefix frontier
  → history site 聚合
```

开放视图忽略 collection terminal marker，因此尾部追加 message 或 tool 不会被结束标记误判为分叉。首次追加的动态内容属于正常新内容；只有后续请求改写、删除、截断或重排上一请求已有内容时，才形成 history site。同一 transition 只计算首次分叉，后续变化不重复累计。

时间相同的相邻关系标记为顺序歧义；缺失或非法时间、投影失败形成不可分析边界；已知 comparison 边界变化形成不可比边界。这些边界不会进入历史变化聚合。

## 生成优化启示

优化启示根据结构事实生成：

- 变量阻断稳定内容：提示在语义允许时调整稳定内容与变量的相对位置；
- 少数固定内容版本并存：提示统一配置来源、模板版本或生成方式；
- 结构化数据等价但文本表示不同：提示使用确定的序列化格式；
- 中途插入内容：提示评估是否可以尾部追加；
- 相同元素顺序不稳定：提示使用确定的生成顺序；
- 历史内容被移动或重排：提示评估是否可以保持追加式组织。

analyzer 输出结构证据和优化启示，不负责确认业务语义，也不自动改写请求。

## 稳定性要求

- 输入请求顺序不改变模板、问题身份和排序。
- detector 执行顺序不改变问题数量和支持度。
- 修改展示文案不改变问题身份。
- 在全部请求前增加相同稳定内容时，绝对 unit index 可以变化，但同一逻辑问题仍能对应。
- 正常动态后缀、不同模板、非模型可见字段变化不会形成问题。
