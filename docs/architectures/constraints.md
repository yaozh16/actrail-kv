# 运行约束

## Receiver

- receiver 的单写入临界区保证每一条 HTTP 请求只能追加为一条完整 NDJSON 记录。
- 非法 JSON 或 JSON non-object body 返回 HTTP `400`；请求体超过限制返回 `413`。
- 若写入发生半行失败，receiver 会回滚到上一个完整记录边界并熔断后续写入，避免把不完整语料交给分析器。
- 输出文件只允许单 receiver 进程写入。
- 写入期间允许分析器读取：Unix 使用写者间的 advisory 文件锁；Windows 使用仅共享读取的打开模式排除第二写者，不额外锁定读取范围。仅属主权限收紧由 Unix 实现，Windows 文件访问权限沿用部署环境 ACL。
- 默认仅监听 `127.0.0.1`。跨主机接入必须由内网反向代理提供 TLS、客户端认证、访问控制和超时，再显式配置监听地址。

## Analyzer 与 Report

- analyzer 与 report 都写入同目录临时文件，成功后以原子 rename 发布最终产物。
- 输入与输出不得是同一文件，也不得指向同一硬链接；失败时不会覆写输入或留下伪完整结果。
- 超限、坏行及未知请求结构会记录为 skipped 原因；不得截断请求后产出高置信 defect。
- 底层语料 I/O 读取失败立即中止分析并返回错误，不重复尝试同一不可读位置。
- report 不访问网络、不重新运行算法；所有来自 payload 的证据都必须 HTML escape。

## 数据边界

完整请求和诊断证据可能包含敏感数据。语料、`analysis.json` 和静态报告必须遵守部署环境的数据分级、访问控制、保留期限和销毁规则。当前工具仅输出可观察结构代理，不包含 tokenizer、模型内部 chat template 或真实 KV 命中数据。
