# 0.2.0 开发需求

## 目标

actrail-kv 以 C ABI 动态库交付 receiver、analyzer 和 reporter 能力，并提供 Rust SDK。外部应用编译一次后，可以在接口兼容的前提下替换动态库并重启，使用更新后的实现。升级无需重新编译或链接外部应用。

receiver 增加进程内函数提交通道。HTTP 与 SDK 共享通道无关的采集服务，保证业务处理和持久化语义一致。

SDK 的 receiver 常态运行并持续持久化，analyzer 按需筛选读取采集存储。analyzer 返回内存中的分析结果，reporter 直接接收该结果并返回报告内容。分析结果和报告仅在显式导出时写入产物文件，CLI 的现有文件生成与读取行为保持不变。

本文描述待实现的 0.2.0 功能。当前命令仍可独立使用。

## 动态库与 SDK

- 分别交付 receiver、analyzer 和 reporter 的 Linux `.so`。调用方按需加载和执行，各能力无需同时运行。
- Rust SDK 封装动态加载、兼容性检查、参数转换、错误处理与资源释放，提供安全的 Rust 调用接口。
- 采集处理、分析算法和报告渲染实现在动态库内。Rust SDK 不静态链接这些业务实现。
- 公开 C ABI 固定符号、类型布局、调用约定、所有权与错误语义。兼容升级保留旧宿主依赖的入口与数据契约。
- 跨 ABI 的业务数据采用 UTF-8 JSON 缓冲区，以指针和长度传递。Rust SDK 提供类型化封装，配置通过 JSON 信封携带完整 TOML 文本并复用现有配置解析。
- 动态库加载不启动 HTTP 服务。宿主显式创建业务实例并触发操作。
- C ABI 可供后续 C++ 绑定复用。本版本交付 Rust SDK，Wasm 绑定和进程内热替换不在本版本范围内。
- 配置以整体传入所属模块，业务模块统一解析。SDK 不复制配置默认值或业务校验规则。
- 独立升级同时遵守存储格式和分析产物格式的兼容要求。
- Rust SDK 使用 `AnalysisOutput` 和 `ReportOutput` 封装原生输出。reporter 直接借用分析结果的 JSON 字节，调用方无需导出或调用文件加载接口。
- analyzer 和 reporter 的处理方法与导出方法分离。配置中的输出路径不自动触发产物写入。

## Receiver 通道拆分

| 层 | 职责 |
| --- | --- |
| HTTP 适配层 A | 路由、HTTP 请求限制、请求解码、headers 到业务元数据的映射、HTTP 响应和错误映射 |
| SDK 适配层 | C ABI 解码、句柄与返回值转换、将函数参数映射为统一采集输入 |
| 公共采集服务 B | 业务输入校验、缺省采集时间补全、采集记录构造、调用存储并返回结果 |
| 存储 | 执行后端写入、并发控制、保留期与存储错误处理 |

- B 的公开输入与输出不包含 HTTP 或 FFI 类型。
- SDK 直接调用 B，不启动 CLI 子进程，也不通过回环 HTTP 发送数据。
- receiver 每次成功提交均完成持久化写入。采集存储由 analyzer 独立按需读取，不增加仅在显式导出时保存的采集模式。
- CLI 仅装配 HTTP 通道。SDK 导出代码即使出现在构建产物中，也不产生自动启动行为。
- 保持现有 HTTP 请求格式、元数据提取规则和成功响应行为。
- HTTP 与 SDK 在后端保存整条记录成功后才返回成功。成功不额外承诺超出存储后端保证的断电持久性。
- 同一语义输入经过两个通道后，得到相同的业务校验结果和记录内容。缺省接收时间按各次调用时刻生成。

## 验收条件

1. 编译固定版本的 Rust 宿主，分别加载两个 ABI 兼容的动态库实现。替换库并重启后观察到新实现行为，宿主可执行文件哈希保持不变。
2. ABI 不兼容或缺失入口的库在加载阶段返回可定位的错误，不进入业务调用。
3. Rust 宿主通过 SDK 提交请求，存储可读到完整记录，运行过程不监听 HTTP 端口、不启动 CLI 子进程。
4. HTTP 与 SDK 覆盖合法输入、非对象请求、元数据缺失或非法、时间戳补全及存储失败的一致性案例。
5. 现有 HTTP 状态码、请求体限制和 headers 映射回归通过。
6. analyzer 与 reporter 可分别加载、按需执行。分析产物可交给另一进程中的 reporter 使用。
7. 验证多次创建与释放、结果及错误缓冲区释放、同一实例并发规则、关闭后的调用限制。
8. 验证不同 reporter 实例的语言设置互不影响。
9. 更新公开接口文档、构建交付说明、Rust 调用示例及文档和代码布局。
10. 验证兼容版本的新 analyzer 与旧 reporter、旧 analyzer 与新 reporter 组合，保留分析产物 schema 的兼容边界。
11. 验证内存配置按显式 `base_dir` 解析路径，宿主工作目录变化不改变已创建实例的存储位置。
12. receiver 持续写入后，analyzer 按筛选条件读取存储，将 `AnalysisOutput` 直接交给 reporter。全过程不生成分析或报告文件，也不调用 reporter 的文件加载入口。
13. 显式导出分析结果和报告，验证导出的文件可被现有 CLI 消费，文件内容不包含 SDK 响应信封。
14. 验证 reporter 借用分析缓冲区时不转移所有权，分析实例关闭后仍可使用其输出，最后由原库释放一次。
