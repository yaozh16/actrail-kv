# 客户能力说明文档要求

## 状态

- 已批准开发。
- 目标读者是使用 Agent、维护 Prompt 或负责 LLM 请求质量的客户工程师。

## 目标

提供一份不依赖内部算法知识的当前能力说明，让客户能够直接判断：

1. 自己遇到的请求构造问题是否属于 actrail-kv 的识别范围。
2. 报告会提供什么证据，以及可以据此检查哪些生成逻辑。
3. 如何启用同一 Session 的跨轮历史分析。

## 内容要求

- 使用具体的 system prompt、memory、RAG、TODO、tools、messages、JSON、tool result 和历史压缩场景描述能力。
- 按“常见现象、actrail-kv 的发现、建议排查方向”组织内容。
- 单独说明提供 Session ID 后可获得的跨轮分析。
- 说明同一模板的后续局部位点是条件性机会，不将其表述为已经实现的收益。
- 说明正常尾部追加、原样保留的动态结果等无需处理的行为。
- 只保留正确使用结果所需的输入条件和解释边界。

## 表达约束

- 不使用 cohort、LCS、symbolic sequence 等内部实现术语。
- 不用测试覆盖率或“直接/条件覆盖/不会误报”等验收语言组织正文。
- 不声称自动理解时间、RAG、画像、摘要等业务语义；只承诺定位其所在位置的变化。
- 不把报告中的结构指标表述为真实收益保证。
- 不描述与 Agent 请求分析无关的系统。

## 必须验收

- 文档中的每个客户案例都有当前代码或验收测试依据。
- JSON 能力明确限定为模型可见字符串中的完整 JSON 或相同标签后的完整 JSON。
- Session 能力明确要求 `X-Actrail-Session-Id` 和线性时间轴。
- 动态尾部、正常追加和无法确定顺序的情况不被描述成优化问题。
- README 和文档布局提供稳定入口。
- 文档不存在内部讨论痕迹、失效能力或无法证明的承诺。

## 已失效决策索引

- 无。
