# LLM KV 缓存结构诊断 MVP

实现设计索引：[`dev/designs/v0.1.0/implementation.md`](../../designs/v0.1.0/implementation.md)。

## 背景

外部网关、Agent 框架或遥测管道已经能够提供包含分析所需字段的完整 LLM 请求。本系统只接收这些数据并做离线结构诊断；采集、网关和真实 KV 命中遥测不属于 MVP。

## 产品价值

从一段时间内采集到的完整 LLM 请求语料中，发现本可共享较长 Token 前缀、却被少量可避免差异过早破坏的结构模式；按结构机会聚合 Top K，并给出能够定位到字段和请求组织方式的证据及优化建议。

## 验收方式

验收只使用完整 HTTP JSON payload，不依赖 tokenizer、模型内部 chat template 或真实 KV 命中数据。以下场景缺一不可：

| Case | 通用识别特征 | 业务样例（仅示例） | 必须识别的结果 |
|---|---|---|---|
| 易变内容位于稳定前缀前部 | 同一请求族在较早位置出现高频变化，而该位置之后反复出现较长、同序的稳定内容 | request ID、tenant、时间戳位于长 system prompt 之前 | 识别易变区域及其后的稳定内容，提示移出模型上下文或后移 |
| 动态值混入稳定文本 | 多个文本序列仅有局部区间变化，变化区间前后均存在显著稳定内容 | system prompt 中嵌入 UUID、当前时间或会话 ID | 聚为同一模板，定位动态槽位和首个分歧位置，不能把整个文本判为不同模板 |
| 动态块位于静态块之前 | 同一结构位置上的整块内容持续变化，而其后的一个或多个块跨请求重复出现 | RAG、memory、用户画像位于固定规则或 few-shot 之前 | 识别“动态块在前、稳定块在后”，提示在语义允许时前移静态内容 |
| 工具定义顺序漂移 | 工具元素可建立稳定的一一对应关系，元素集合及各自内容相同，但序列位置发生变化 | 相同 tools 在不同请求中按注册顺序或哈希遍历顺序输出 | 识别为顺序不稳定，不能误判为工具增删或不同模板 |
| 工具定义微小漂移 | 可由稳定身份和主体结构对应到同一工具，但其局部内容或表示方式形成多个近似变体 | 同名工具的 description、schema 文本或字段组织略有变化 | 定位具体工具及差异位置，识别其后被阻断的稳定上下文 |
| system prompt 微小漂移 | 同一角色、同一结构位置的文本整体高度相似，较早的局部差异之后仍有较长公共内容 | 提示词靠前位置出现标点、空白或少量措辞版本差异 | 识别为同一近似模板的版本漂移，并定位首个差异 |
| 历史消息非追加式组织 | 有序消息序列之间存在较长公共子序列，但该子序列因插入、删除、裁剪或重排而不再保持相同前缀位置 | 新消息前插、历史倒序，或滑动窗口裁掉前部消息 | 识别稳定公共历史及其位移，报告非 append-only 造成的前缀破坏 |
| 模型可见内容格式漂移 | 模型可见内容在语义结构上等价，但其可观察文本或字节表示不稳定 | prompt 内嵌 JSON 的缩进、换行或集合顺序不同 | 识别语义等价但模型可见表示不同的格式漂移；不得把 HTTP 外层 JSON 序列化差异当成该问题 |
| 正常动态后缀 | 差异仅发生在共同稳定前缀之后，且差异位置之后不存在可恢复的稳定内容 | system、tools 和历史相同，仅最后一个 user message 不同 | 不得报告为缓存破坏，不得进入 Top K |
| 真正不同的模板 | 差异是广泛、持续或结构性的，无法由少量槽位、局部编辑、位移或重排解释 | 翻译 Agent 与代码审查 Agent 使用不同指令和工具集合 | 必须分成不同模板，不得强行合并并生成优化建议 |
| 非上下文字段变化 | 差异只存在于不会进入模型上下文投影的字段 | temperature、max_tokens、stream 或 trace metadata 变化 | 不得报告为上下文前缀破坏 |
| 不可直接比较的请求 | 请求无法映射到同一个可靠的模型上下文组织域 | provider、payload dialect 或 model 不同 | 必须隔离分析，不得仅因局部文本相似而跨域比较 |

上述识别特征必须由请求集合之间的相对结构、位置和稳定性推导；实现不得依赖某个业务字段名、某类动态值格式或某家 provider 的固定 payload 形状。具体字段和值只能作为诊断证据，不能作为识别规则本身。

每个被识别的正例至少输出：模板簇、首个分歧的 JSON 路径或文本位置、分歧后仍稳定的可观察内容、受影响请求数、诊断类型和优化建议。同一根因只能聚合为一个问题，不能用请求两两组合占满 Top K。

Top K 使用混合 fixture 验收：高影响 case 的受影响请求更多且分歧后稳定 UTF-8 字节更多，中、低影响 case 依次减少；`top_k=3` 必须依次返回高、中、低三个聚合问题。正常动态后缀、真正不同模板、非上下文字段变化和跨域请求不得进入榜单；打乱输入行顺序后结果与排名必须保持不变。
