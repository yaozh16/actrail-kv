# 结构复用率与优化空间需求

## 背景

报告此前只回答"哪里有问题"（缺陷列表），不回答"离目标还差多少、靠什么补"。
业务目标是支撑 KV 利用率提升到 90%，因此需要把散落在会话证据与缺陷证据里的量
收敛成一个可引用的复用率，并给出可执行的机会清单。

收益一律用**字节与结构占比**表达：没有真实 usage 时不声称 KV miss，也不换算 token 或金额。

## 目标

1. analyzer 输出 `prefix_reuse`：
   - 会话对口径的复用率（Σ 公共前缀 / Σ 上下文）、逐会话明细；
   - 逐请求上限（当前公共前缀 + 该请求所涉缺陷中最大的被阻断稳定字节，封顶为该请求上下文长度）
     与增益最大的请求列表（按增益降序，最多 500 条）；
   - 三段字节构成 `composition`：已复用 / 已知可恢复 / 每轮新增，三者之和严格等于上下文总字节。
2. report 首屏新增「结构复用率」区块：刻度条呈现当前值、补完已知结构问题后的上界与 90% 目标，
   并在补完仍不达标时说明剩余部分属于每轮新增内容；90% 目标写死在报告层，不进入 `analysis.json`。
3. Top K 表格**保留名称**，只增加三列：位置、建议动作（复用缺陷自带的 `insights[].summary`）
   与跳转到证据的锚点；名次与排序仍等于 `top_k[]`，不引入第二种排序口径。
4. 首屏给出「结构代理 vs 真实命中」对照表：按会话并列结构复用率与 `basis = reported` 的真实命中率及差值；
   没有真实 usage 的会话不参与对比。

## 验收

- 两份基线语料分别得到 68.6% 与 84.4%（±0.1pp），与人工计算一致；
- `composition` 三段之和严格等于 `context_bytes`；
- Top K 表格的名次顺序等于 `top_k[]` 的顺序，未引入第二种排序口径；
- 全部为估算口径时不渲染对照表，只给一句说明；
- 上界在 `analysis.json` 与报告中都标注为结构上界，不出现 token 或金额换算。
