# HTML 报告编译期模板

## 背景

HTML renderer 使用 Rust 字符串和 `write!` 拼装页面外壳、样式及多个报告区块。
静态结构分散在渲染函数中，修改页面布局时需要同时理解数据计算、本地化与 HTML 转义，
单文件和单函数职责过重，也容易遗漏对不可信内容的转义。

## 目标

1. 使用模板文件描述 HTML 页面外壳、静态 CSS 与重复区块，不在 Rust 中集中拼接静态 HTML。
2. 模板在编译期解析并嵌入 `actrail-kv-report` 二进制；运行时不得读取外部模板文件。
3. 固定用户文案继续由现有 locale catalog 提供，HTML 模板不新增第二套翻译来源。
4. 业务聚合、排序、百分比、字节格式化、短 ID 与空态判断继续由 Rust 完成。
5. 保持现有 HTML 报告的信息内容、区块出现条件、zh-CN/en-US 行为和自包含属性。
6. Markdown renderer 保持独立，不从 HTML 反解析，也不因本次重构改变输出。

## 展示模型

模板只消费面向展示的 view model。view model 中的文案、数值和状态必须已经完成本地化与格式化；
模板只负责条件、循环、静态结构和字段插入。不可信数据以原始文本进入模板，由模板引擎统一转义。

## 模板边界

- 根模板负责文档头、CSP、语言、全局样式和报告区块编排。
- CSS 集中到独立模板资源，不再由各个 Rust 函数分别生成 `<style>`。
- Top K、缺陷、前缀复用、会话证据、缓存指标和前缀树使用独立区块模板。
- 复杂 SVG 只把已计算的节点、坐标和标签传给模板，不在模板中实现业务计算。

## 验收

- zh-CN 与 en-US 报告仍具有正确的 `lang`、标题、表头和固定文案。
- 同一输入生成相同的区块集合、关键数值、链接与空态。
- 请求内容、ID、路径、模型名和摘录仍经过 HTML 转义，现有 XSS 回归通过。
- 删除构建目录中的模板源文件后，已构建二进制仍可生成报告。
- HTML 输出允许模板排版产生的非语义空白差异，页面文本和 DOM 结构保持等价。
- `cargo test -p actrail-kv-reporter`、workspace 单测及现有端到端脚本通过。
