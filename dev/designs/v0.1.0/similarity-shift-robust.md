# 候选文本相似度实现设计

## 方案

把“等距位置采样 shingle”替换为“全窗口 4 字节 shingle 的 bottom-k min-hash 采样”：

- 枚举文本全部 4 字节窗口，计算 FNV-1a 哈希；
- 保留哈希值最小的 `MAX_SHINGLES_PER_UNIT`（256）个作为该文本的采样集合；
- Dice 系数仍按采样集合计数计算。

相同内容发生局部插入/删除后，未受影响窗口的哈希集合保持不变，因此采样集合大部分重叠，相似度对位移不敏感；采样选择与文本位置无关，保证确定性。

## 预算

- 扫描一次文本的全部窗口：`O(len)` 次哈希，常数 4 字节/窗口；
- bottom-k 用容量 256 的最大堆：`O(len * log 256)`；
- 与逐字节编辑距离不同，不产生 cells 预算；仍受 `max_text_unit_bytes` 限制。

## 边界

- `left == right` 仍走线性 fast path，不扫描；
- 短文本（<4 字节）退化为逐字节集合；
- 该指标只用于候选召回，不参与模板稳定内容判定。
